# EXTN 7.5 — AI-Ready Enterprise Application Foundation（规划）

> 状态：**Low-Code Agent Kit 的 EXTN 工具实施计划**，不是 EXTN 产品版本规划的真源，也不是正式发布说明。跨仓产品目标与 7.1–7.5 各版本开发计划见 [eaextn/extn-home 产品路线图 PR #3](https://github.com/eaextn/extn-home/pull/3)；本仓只维护 Skills/MCP 交付。当前可核对的后端基线仍为 7.0.0-RELEASE。7.5 由 EXTN 各源仓独立升级、验收及发布；此工具仓不修改 EXTN 数据库或生产环境。

## 一、产品目标

把 EXTN 从“以人工设计器操作为中心的低代码平台”，演进为**AI Coding 可理解、可修改、可验证的企业应用运行基座**：

- AI 做需求解释、设计差异、生成和验证；EXTN 执行真实权限、数据、业务约束、流程及发布。
- AI 直接复用现有 VisualDev、数据集、字典、Flowable、组织权限、报表/Univer；不在 Kit 中复制业务引擎。
- **统一模型来源**：设计器、Coding Agent 和运行态继续使用同一个 EXTN 配置/业务对象。Kit 只做可审查的只读上下文投影，不创建第二套表单数据库。
- **先支持存量修改**：不以“一句话造新系统”为唯一指标，更要支持分析已有表单/关联/权限及升级影响。

## 二、双受众区别

| | 开发设计端 | 企业最终用户端 |
| --- | --- | --- |
| 目标 | 中文友好的交付与 AI Coding 协作 | 进入应用即获得适合本地的业务体验 |
| AI | Skills/MCP + Codex/Claude/其他 Agent；AI 生成提案，人工微调 | 业务助手通过业务服务和权限界面工作；高风险操作由用户确认 |
| 国际化 | 控件库、主要设计器 UI；高级设置允许中文 | 主要 UI 自动按部署/个人语言显示；允许少量中文回退，非逐字段强制 I18nCode |
| 数据 | 原始配置、流程版本和业务代码可追溯 | 不因翻译、提示词或模型结果改变主键/字典/审批权限 |
| 验收 | 可解释改动/可回滚/可重做 | 交付后真实业务可用、安全、可审计 |

## 三、职责与技术架构

**EXTN 7.5 产品核心（原仓负责）**

- 权限/租户、业务数据、Flowable 和表单定义的原生最终执行与校验。
- 配置的来源版本、已有审批/发布/回滚及日志；必要时增加轻量“变更检查”服务，复用现有能力，不做第二套发布中心。
- 已有 AI 中心及 MCP/Skills 管理继续做平台内 AI 应用能力。当前检查到独立 MCP 示例主要是天气工具，不能直接视为 Coding 业务接口。

**lowcode-agent-kit（本仓负责）**

- EXTN-first Skill + MCP 入口，读取受当前用户授权的业务表单、工作流、数据字典。
- 只读 Context Projection：从返回的 VisualDev 定义解析 fields / __config__ / 字典 / 表 / 接口及流程标记，省略脚本和业务数据行，供 Agent 分析。
- 离线变更计划、语义校验和测试夹具，后续再提供经批准的配置写入适配。
- 保持 EAP/OpenBPM 的兼容适配，不让其 API、Activiti 语义决定 EXTN 的新架构。

## 四、分阶段交付

| 阶段 | 产物 | 验收 |
| --- | --- | --- |
| **P0 — 当前 Kit** | form.catalog/context、表单/字段/流程/版本/字典只读查询；extn_analyze_definition 与 extn_preview_definition_change 离线摘要和字段级影响预览；默认 EXTN Skill | 真实 MCP 握手、模拟 HTTP、离线解析、无凭据不读取 |
| **P1 — EXTN 7.5 设计基础** | 应用/表单/流程/字典/数据服务的稳定语义引用、关系图、版本与权限上下文、元数据缺口报告 | 在隔离 DEV 实例拿真实授权数据，能发现并解释至少一个已有表单的依赖 |
| **P2 — 安全变更闭环** | inspect → plan → validate → review → apply(dev) → verify，审查差异、冲突检测与回退证据 | 典型表单/字典/审批变更，无新增客户数据丢失，失败可回滚 |
| **P3 — 交付产品化** | 需求/截图/现有模块 → AI 方案 → EXTN 元数据/源码 → 回归测试及交付证据 | 以实际团队总耗时、修改耗时、返工率衡量 |
| 远期（按需） | 受原业务权限管控的用户端 Agent 与审批协作 | 不通过 Coding MCP 复用生产业务写权限 |

P0 首批新增能力来自已核对的控制器路由：`/api/visualdev/Base`、`/api/visualdev/Base/{id}`、`/api/workflow/template[/Info|/Version]/{id}` 等。**源码具备接口不等于目标 DEV 服务已经部署且授权**。

## 五、尽量少改原有 EXTN

1. 首期不修改 EXTN 代码、数据库和设计器 JSON。
2. 非通用需求由 Skills 指导现有 API，避免对单个控件增设 AI 专属字段。
3. 先以外部 stdio MCP 适配为主；只有 REST 无法确保身份、事务或幂等时，才评估在 EXTN 增加单独可选模块。
4. 不复制平台内部旧的示例 MCP 服务，不把天气 demo 认定为生产 Coding 能力。
5. 不引入完整 RAG、第二套 Agent 编排、模型网关或新低代码设计器。

## 六、回归与安全边界

- EXTN：按应用+租户+身份终判权限；读取表单详情仍须具备 VisualDev 对应权限。
- 不将 JS 事件脚本/富文本/历史业务记录作为工具指令；分析器只返回结构摘要。
- 防止大批量枚举：目录只返回固定第一页最多 20 项；之后设计真实用户授权的分页协议。
- 不暴露任意 REST/SQL/Shell，不开放生产写入、审批、发布权限。
- P1 实测须证明租户数据不串用、权限拒绝不降级为管理员、表单 JSON 没被分析器改写。
- P2 才讨论业务配置写入，且需审批、版本冲突处理、幂等与审计；与 EXTN 7.5 发布审批分开。
